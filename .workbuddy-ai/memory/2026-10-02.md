## 踩到的坑（都已在文档里记录）

### 1. `uv sync` 不装 workspace 成员

`uv sync` 默认只装根项目依赖，6 个成员包一个都不装。
必须 `uv sync --all-packages`。已写进 README 与 setup.md。

### 2. 内存 SQLite 的多连接隔离

测试用 `sqlite:///:memory:` 会导致随机的 `no such table` ——
SQLite 的内存库是「每连接一个独立数据库」，连接池换连接就看不到表。
改用临时文件数据库。

### 3. 代理环境变量劫持 127.0.0.1

开发机上的 `http_proxy` 会把发往 mock 站点的请求也转出去，
症状是「mock 站点连不上」，看起来像服务没起。conftest 里统一清除。

### 4. YAML 双引号里的 `\S` 是非法转义

`regex: "作者：(\S+)"` 会直接让 YAML 解析失败。正则必须用单引号。

### 5. XPath 的 `@class="x"` 是精确匹配

节点上还有别的类名（`class="book-item odd"`）就匹配不上，要写 `contains(@class,'x')`。

| Bug | 后果 | 修法 |

## 版本号统一为 0.1.0.dev0（改成了单一来源）

用户要求把版本号统一为 `0.1.0.dev0`（PEP 440）。借这次机会把原本
**14 处分散定义**（7 个 pyproject + 6 个 `__init__.py` + 1 个 package.json）
改成单一来源：

- 唯一手写点：`packages/inkflow-core/src/inkflow_core/__init__.py` 的 `__version__`
- 成员包 pyproject：`dynamic = ["version"]` + `[tool.hatch.version] path`
  **跨目录**读取 core 的 `__init__.py`（实测可行）
- 成员包 `__init__.py`：`from inkflow_core import __version__` 转发
- 根 pyproject：展示用，与来源一致
- 桌面端：npm 是 semver 生态，用等价写法 `0.1.0-dev.0`
- 新增 `scripts/check_version.py`，已接入 `scripts/check.py` 与 CI

实测结果：`uv sync --all-packages` 后 6 个包全部为 `0.1.0.dev0`，
运行时 `import inkflow_*.__version__` 也全部一致。

副作用（已写进 ADR-014 与 setup.md）：成员包用了动态版本，
不能脱离 workspace 单独 `pip install`。

## 上线 GitHub + CI/CD

仓库：**https://github.com/luoqingciya/InkFlow**（public，SSH remote）

### 流水线

- **CI**（push / PR）：版本号一致性 → ruff → mypy → pytest，矩阵 Ubuntu + Windows；
  另有桌面端类型检查与构建
- **Release**（push tag `v*`）：三平台 PyInstaller 打包后端 → **冒烟测试** →
  取回对应平台后端 → electron-builder 打安装包 → 创建 Release

### 关键设计

- **PyInstaller 不能交叉编译**，所以后端必须在三个平台各打一次
- **打包后立刻冒烟测试**：PyInstaller 的失败往往是静默的（构建成功、
  一运行就 ModuleNotFoundError），只看「构建通过」会把问题漏给用户
- 桌面端生产模式直接执行随包分发的后端，不再依赖用户机器上的 `uv`
- 图标用 `scripts/make_icon.py` 纯标准库生成（可复现、可调色），
  没有引入图像处理依赖，也没消耗图像生成额度

### 实测结果

```text
dist/inkflow-server.exe   28.2 MB（单文件）
冒烟测试：
  [后端] INKFLOW_READY port=63648 token=...
  [健康检查] {"status":"ok","version":"0.1.0.dev0","uptime_seconds":0.11}
冒烟测试通过
```

### 第一次 CI 失败（三个问题，根因都是「改完没本地验证就提交」）

1. **Windows runner 控制台编码**
   `UnicodeEncodeError: 'charmap' codec can't encode` —— GitHub Actions 的
   Windows 环境 stdout 默认是 cp1252，脚本打印中文直接崩。
   修复：脚本入口 `sys.stdout.reconfigure(encoding="utf-8")` 兜底 +
   CI 设 `PYTHONUTF8=1`（PEP 540 的 UTF-8 模式，比只设 PYTHONIOENCODING 彻底）
2. **`make_icon.py` 未格式化** —— 写完脚本没跑 `ruff format` 就提交
3. **TS 类型错误** —— `stdio: ['ignore','pipe','pipe']` 时 spawn 返回
   `ChildProcessByStdio<null, Readable, Readable>`，断言成
   `ChildProcessWithoutNullStreams` 不成立（stdin 是 null）。

教训：`scripts/check.py` 原先只覆盖 Python 侧，改完前端不会报错。
已给它加上前端类型检查（有 node_modules 就跑）。

### Release 流水线的两个坑

1. **Windows runner 的默认 shell 不是 bash**：`ls -la` 会交给 PowerShell，
   而 PowerShell 里 `ls` 是 `Get-ChildItem` 的别名，不认识 `-la` 参数，
   报 "A parameter cannot be found that matches parameter name 'la'"。
   跨平台命令必须显式写 `shell: bash`。
2. **后端产物同名互相覆盖**：Linux 与 macOS 的 PyInstaller 产物都叫
   `inkflow-server`，汇总到同一目录时后写入的覆盖先写入的，
   最终 Release 里只剩一个。修复：按平台重命名后再汇总。

### 踩坑

- **spec 里的相对路径是相对运行时 cwd**，不是 spec 文件所在目录。
  要用 PyInstaller 注入的 `SPECPATH`，否则从仓库根跑会找不到入口
- **Windows 上进程刚终止时文件句柄未释放**，删临时目录会 PermissionError。
  冒烟测试用 `TemporaryDirectory(ignore_cleanup_errors=True)` ——
  要验证的是「后端能不能起来」，不是「临时目录能不能删干净」
